# 03_ストックバスケット機能 (Stock Basket)

## 1. 目的

ユーザー独自の視点や投資テーマに基づき、複数の銘柄を詰め合わせた「バスケット（カゴ）」を構築・管理することを目的とする。
実際の保有資産（リアルポートフォリオ）とは切り離し、理想の組み合わせや、特定の市場セクターの動向を「セット単位」で観察するための機能である。

## 2. ユーザーストーリー

* ユーザーは、「2026年本命」「半導体セット」「高配当バスケット」など、自由な名前で複数のバスケットを作成できる。
* ユーザーは、作成したバスケットを切り替えることで、異なる投資テーマの現在状況を瞬時に把握できる。
* ユーザーは、個別の銘柄の動きだけでなく、バスケット全体の騰落率を見て、自分の仮説が正しいかを評価できる。

## 3. 主要機能 (機能要件)

### 3.1 バスケット管理

* **バスケットの編成・編集・削除**: 複数の銘柄を1つの「カゴ」としてまとめて管理する。
* **テーマ（バスケット名）設定**: 「割安株」「景気敏感」など、戦略がわかる名前を付与できる。

### 3.2 銘柄（ストック）管理

* **バスケットへの投入**: 銘柄コードや企業名検索から、対象のバスケットへ素早く銘柄を追加できる。
* **銘柄の整理**: バスケット内での並び替えや、別のバスケットへのコピー・移動ができる。

### 3.3 モニタリング・分析表示

* **バスケット一覧ビュー**: 最新価格、前日比、騰落を銘柄ごとに表示する。
* **バスケット・スタッツ (将来機能)**: バスケット全体の平均騰落率や、日経平均等との相関を表示し、テーマごとの市場の強弱を可視化する。

## 4. UI/UX イメージ

* **「市場監視」メニュー**: 保有資産（Assets）とは別のメインメニューとして配置。
* **バスケット・タブ**: 画面上部のタブやサイドバーで複数のバスケットを切り替え、ドラッグ＆ドロップで銘柄を入れ替えられる直感的な操作感を目指す。

# 04_東証上場銘柄マスタ更新仕様書

## 1. 目的

日本取引所グループ（JPX）が公開している最新の上場銘柄リストを取得し、システム内の銘柄マスタ（`spt_stocks`）の名称やコード等の情報を最新の状態に更新する。

## 2. 準備（データソース）

* **ソース名**: 日本取引所グループ公式統計資料（東証上場銘柄一覧）
* **URL**: [その他統計資料 | 日本取引所グループ](https://www.jpx.co.jp/markets/statistics-equities/misc/01.html)

---

## 3. 更新手順

### ステップ1：最新データのダウンロード

1. 上記URLにアクセスする。
2. 「統計資料」セクションにある**「その他統計資料」**内の**「東証上場銘柄一覧」**（Excelファイル）をクリックしてダウンロードする。

### ステップ2：データの抽出（Excel操作）

1. ダウンロードしたExcelファイルを開く。
2. データが記載されているシートを選択し、全ての列（A列〜J列など、データが存在する範囲全体）を選択する。
3. `Ctrl + C` を押下し、クリップボードにコピーする。

### ステップ3：システムへの取り込み

1. 本システムの**「銘柄マスタ更新ページ」**（または管理画面内の該当URL）にアクセスする。
2. 入力エリア（テキストエリア）に、コピーしたExcelの内容を貼り付ける。
3. 画面上の**「取り込み処理」**ボタンを押下する。

---

## 4. 処理仕様（内部ロジック）

取り込み処理が実行されると、システム内部では以下の処理が行われる。

| 処理ステップ | 内容 |
| --- | --- |
| **パース処理** | 貼り付けられたタブ区切り（TSV形式）のテキストを解析し、コード・銘柄名・市場区分等を抽出する。 |
| **バリデーション** | 銘柄コードが4桁の数字（または英字混じり）であることを確認する。 |
| **DB更新 (UPSERT)** | 銘柄コードをキーとして、`spt_stocks` テーブルの既存情報を更新、存在しない場合は新規登録を行う。 更新対象は「spt_stocks」「jpx_company_master」とする|

---

## 5. 注意事項

* **データ構造の変化**: JPX側のExcelの列構成が変更された場合、ステップ3の「パース処理」に失敗する可能性があるため、定期的なメンテナンスが必要。
* **実行タイミング**: 銘柄の新規上場や市場変更は頻繁に行われるため、月1回程度の更新を推奨。

# 05_user_account_broker
## 概要

本システムでは、ユーザーごとに異なる「証券会社」「口座区分（NISA等）」「手数料体系」を柔軟に管理できる構造を採用します。特に複雑な証券会社の手数料体系を正確にシミュレーションするため、「標準マスタ」と「個別スナップショット」を切り替えるハイブリッド方式で設計します。

## 手数料管理の柔軟性

* **多対多の口座紐付け**: 1人のユーザーに対して複数の証券口座（松井、野村等）を紐付け可能。
* **標準パターンの適用**: 証券会社ごとに複数の手数料パターン（パターン1、プランA等）をマスタとして定義し、ユーザーは口座ごとに最適なものを選択。
* **個別カスタマイズの独立性**: 標準パターンから条件を変更・追加する場合、その口座専用の独立したルールデータ（`account_fee_rules`）を生成します。これにより、マスタの改定に左右されない確実な計算と、柔軟な個別調整を両立させます。
* **マスタ改定への対応**: 手数料改定時には `fee_rules` に新しい有効ルールを追加します。個別カスタマイズを行っていないユーザーには常に最新のアクティブなマスタールールが適用され、カスタマイズ済みの口座は独立性が担保されます。
